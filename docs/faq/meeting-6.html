Часть 1. Общие вопросы о курсе и подходе

Заведи одну мета-папку с общим файлом-инструкцией на корневом уровне - там описание всех направлений и где что лежит. Внутри - подпапки по смысловым кластерам, каждая со своей структурой. Например, всё, что касается продаж - в одной подпапке с CRM/outbound/meetings внутри неё.

Базового уровня подписки достаточно для личной продуктивности без кодинга. Если интенсивно готовишь контент - понадобится уровень выше. Чтобы понять, куда уходят токены, попроси сам Claude Code проанализировать историю твоих разговоров и найти точки утечки - например, хук, который срабатывает слишком часто.

Два уровня защиты. Первый - попроси сам Claude сделать security review репозитория перед установкой. Второй - не отключай permission-подтверждение по умолчанию, это вторая линия защиты, даже если review прошёл чисто. Практическое правило: не ставь пакеты младше 7 дней с момента публикации, лучше 30 - за это время сообщество успевает найти уязвимости, если они есть.

Используй браузерную автоматизацию как universal fallback - попроси Claude Code открыть сайт и сделать то же самое руками через браузер. Медленнее прямого API-подключения, но закрывает почти все случаи, где готового MCP ещё не существует.

Да, рабочий путь такой: ресерч → MD-файл с описанием каждого слайда (title, подзаголовок, мысль, что визуально показать) → официальный pptx-скилл превращает это в файл → финальная вычитка глазами. Самое слабое место - подбор картинок с внешних сайтов, здесь ИИ пока справляется хуже всего, картинки часто приходится подбирать самому.

Две причины. Первая - сжатие контекста (compaction): когда разговор становится слишком длинным, часть деталей теряется при автоматическом сжатии, лучше делать это вручную с явным фокусом на важном. Вторая - на очень длинных разговорах модель объективно хуже помнит середину диалога, чем начало и конец. Если разговор становится критически важным и длинным - начинай новую сессию с кратким резюме, а не тяни старую до бесконечности.

Если бьёшься с одной моделью 30-60 минут без результата - подключи вторую точку зрения, другую модель. Не нужно упорствовать в одиночку с одним и тем же инструментом.

Правило 80/20: 80% объёма работы делай с ассистентом, это быстро. Но финальную проверку в по-настоящему узкой экспертной области отдавай человеку-куратору - особенно пока у тебя самого не наработалась интуиция, в каких именно местах модель начинает "плыть" и выдавать неточности.

Риск реальный, и его стоит держать в голове осознанно: чем больше делегируешь ИИ, тем важнее сознательно оставаться "в контуре" и не терять базовые навыки, которые всё ещё иногда придётся применять самому, без ассистента под рукой.

Курс закрывает первый шаг - личную продуктивность каждого сотрудника с ИИ. Следующий фронтир, уже за рамками этих шести встреч, - продуктивность всей компании и её процессов целиком. Первый росток этого ты уже видел на встрече 5, в модели "команда агентов, где один раздаёт задачи другим" - именно в эту сторону имеет смысл двигаться дальше, используя план внедрения из Блока 3 встречи 6.

Часть 2. Технические проблемы и типичные ошибки по встречам

Встреча 1 · Настройка Claude и онбординг

Проверь, что скачана актуальная версия по ссылке code.claude.com/docs/en/desktop, а не со стороннего источника. На Windows иногда требуется обновление PowerShell - если видишь такую ошибку, попроси сам Claude Code подсказать нужную команду обновления.

Это известный баг интерфейса десктоп-версии, не твоя ошибка. Не перетаскивай архив в чат - вручную положи zip-файл в рабочую папку курса через проводник, а затем попроси Claude Code: "поставь скилл из этой папки", указав путь. После установки перезапусти сессию, иначе новая команда не появится.

Скорее всего, Claude Code установлен не в отдельной чистой папке под курс, а в папке с рабочими файлами. У ассистента появился доступ к тому, что не относится к курсу. Создай новую чистую папку и работай только в ней.

Скорее всего, файл-инструкция получилась расплывчатой ("работаю в компании, помогай мне" вместо конкретики). Чем расплывчатее "Правила" - тем более общие ответы даёт модель. Открой файл-инструкцию текстом и перепиши конкретнее: роль, задачи, тон. Или заново пройди онбординг, отвечая максимально развёрнуто.

Единственный надёжный способ - открыть новую сессию Claude Code в рабочей папке (не ту, где шёл онбординг) и явно спросить "как меня зовут" или "какая у меня роль". Если ответил правильно - всё сработало, если нет - файл-инструкция не подгружается, нужно разбираться заново.

Встреча 3 · Автоматизация календаря, почты, Telegram

Если и это не помогает - попробуй проверенный прокси, например, https://astroproxy.com/, - попроси Claude помочь настроить его (VPN, даже платные, не всегда полностью скрывает IP). Если ничего не работает и номер российский - попроси знакомого за границей сгенерировать API-ключи или используй зарубежный номер.

Убедись, что установлен Python 3.10 или новее - проверка командой python --version. Без него не запустится скилл telegram-mcp-setup, который ставит нужный пакет через pip.
