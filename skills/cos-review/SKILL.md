# /cos-review - автоматическая самодиагностика

Это автоматизированная версия чек-листа самодиагностики (встреча 5, Блок 2 / встреча 6, Блок 1) - вместо того чтобы человек сам отмечал галочки, скилл сканирует реальные файлы и настройки и считает баллы сам.

Определи режим по тому, что написал человек:
- **status** (или ничего не указано) - только посчитать и показать баллы
- **setup** - посчитать баллы и предложить помощь по самым простым пробелам
- **review** - посчитать баллы и сравнить с прошлым результатом

## Уровень 1. Знает тебя (до 5 баллов)

Проверь в рабочей папке:
- Есть `CLAUDE.md` → +1
- Есть `goals.md` → +1
- Есть `SOUL.md` → +1
- Есть папка `atomic/` и в ней хотя бы 3 файла → +1
- Есть папка `notes/` с файлами `daily-log-*.md`, хотя бы 3 записи → +1

## Уровень 2. Имеет источники (до 5 баллов)

Прочитай `~/.claude.json`, посмотри секцию `mcpServers` (и, если есть доступ, список коннекторов Claude Desktop). Ищи по названиям серверов (регистр не важен):
- Есть что-то с "gmail" в названии → +1
- Есть что-то с "telegram" в названии → +1
- Есть что-то с "anysite" в названии → +1
- Есть что-то с "chrome" или "browser" в названии → +1
- Есть что-то с "calendar" или "gcal" в названии → +1

Если файл `~/.claude.json` недоступен или нет прав на чтение - скажи об этом честно и попроси человека перечислить подключённые MCP словами, вместо того чтобы гадать.

## Уровень 3. Знает процедуры (до 5 баллов)

Проверь папку `.claude/skills/` (и в рабочей папке, и в `~/.claude/skills/`):
- Посчитай количество папок со скиллами (каждая содержит `SKILL.md`) → +1 за каждый скилл, максимум 4 балла
- Если суммарно скиллов + часто используемых команд (`/atomize`, `/council`, кастомные) не меньше 5 → +1

## Уровень 4. Проактивен (до 5 баллов)

- В `~/.claude.json` или в настройках Claude Desktop есть хотя бы один Schedule Task → +1
- Telegram подключён так, что бот может написать первым (n8n-бот или scheduled task с доставкой в Telegram) → +1
- Есть папка `.claude/agents/` хотя бы с одним `.md`-файлом субагента → +1
- В `.claude/settings.json` или `~/.claude/settings.json` есть непустая секция `"hooks"` → +1
- Если все четыре пункта выше выполнены → +1 (бонус за полную систему)

## Уровень 5. Доставляет результат (до 5 баллов)

Это нельзя просканировать по файлам - спроси человека напрямую через `AskUserQuestion`:

**Вопрос:** "Как оценишь регулярность результата - от простого пользования системой до ежедневной публикации?"
**Варианты:**
- "0 - в основном экспериментирую в песочнице" (0 баллов)
- "1-2 - иногда использую для реальных задач" (1-2 балла, уточни на глаз)
- "3-4 - регулярно получаю полезные результаты" (3-4 балла)
- "5 - работает каждый день, реальные результаты, публикую" (5 баллов)

## Подсчёт и ранг

Сложи баллы всех пяти уровней (максимум 25) и определи ранг:

| Баллы | Ранг |
|---|---|
| 0-5 | Стажёр |
| 6-10 | Младший сотрудник |
| 11-15 | Сотрудник |
| 16-20 | Старший сотрудник |
| 21-25 | Правая рука |

## Вывод результата

Покажи компактно, по образцу:

```
Самодиагностика цифрового сотрудника

L1 Знает тебя         ███░░  3/5
L2 Имеет источники     ████░  4/5
L3 Знает процедуры     ██░░░  2/5
L4 Проактивен          █░░░░  1/5
L5 Доставляет результат ███░░  3/5

Итого: 13/25 - Сотрудник
```

Затем перечисли конкретно, чего не хватает по каждому уровню, где балл не полный (например: "L1: нет SOUL.md, нет заметок в atomic/" / "L4: нет Hooks, нет субагентов").

## Режим setup - помощь закрыть пробелы

Если человек запустил в режиме `setup`, после вывода результата:

1. Возьми 1-2 САМЫХ ПРОСТЫХ пробела (не все сразу - иначе это превращается в отдельный урок посреди диагностики).
2. Предложи конкретное действие с явным вопросом через `AskUserQuestion`, например: "Хочешь, я прямо сейчас создам SOUL.md?" или "Хочешь, напомню, как установить скилл telegram-mcp-setup со встречи 3?"
3. Для пробелов, которые требуют долгого процесса не по одному файлу (например MCP-подключений, Hooks) - не делай их сам за человека, а укажи, к какой встрече курса вернуться за инструкцией:
   - Нет CLAUDE.md/goals.md → скилл онбординга, встреча 1
   - Нет atomic-заметок → скилл atomize, встреча 2
   - Нет MCP-источников → встреча 3 (Telegram, почта) или встреча 4 (AnySite)
   - Нет скиллов/субагентов → встреча 4 (researcher-агент) или встреча 5 (модель найма)
   - Нет Schedule Task/Hooks → встреча 5, Блок 3-4

## Режим review - сравнение с прошлым

Если человек запустил в режиме `review`:

1. Проверь, есть ли файл `notes/cos-review-history.md`. Если нет - создай с заголовком `# История самодиагностики`.
2. Найди последнюю сохранённую запись (формат ниже) и покажи разницу по каждому уровню и по итогу ("L3 выросла на 2 балла, было 11, стало 16 - Старший сотрудник, было Сотрудник").
3. Если прошлых записей нет - скажи, что это первый замер, сравнивать не с чем, и просто сохрани текущий.
4. Добавь новую запись в конец файла:
```markdown
## ГГГГ-ММ-ДД
L1: X/5, L2: X/5, L3: X/5, L4: X/5, L5: X/5
Итого: X/25 - [ранг]
```

## Тон

Не для соревнования с кем-то, а чтобы видеть свой реальный прогресс - держи этот тон в комментариях к результату. Не критикуй низкий балл, не хвали формально высокий - просто показывай факты и куда двигаться дальше.
